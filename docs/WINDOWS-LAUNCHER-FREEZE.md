# Launcher Windows — preparação e freeze

O packaging não compila o C++ durante o staging. O launcher para o Setup tem de ser preparado **antes** de propor o freeze:

1. Com um HEAD revisto e worktree rastreado limpo, correr `node scripts/windows-launcher-proof.mjs --prepare` em Windows com CMake e MSVC. São feitas duas compilações Release limpas e comparados os bytes. A versão do produto, PE x64 e strings do contrato NSIS são inspecionados. O input anterior é copiado para o diretório de evidências da primeira compilação antes de se substituir o input de build; o manifesto anterior deixa de corresponder. Não altera a instalação do utilizador nem escreve uma aprovação.
2. Correr `node scripts/windows-launcher-proof.mjs --verify` e os testes necessários, incluindo os LAB nativos de identidade e handoff em ambiente autorizado. As strings são apenas diagnóstico: não provam comportamento, integridade ou origem por si só. O rebuild prova apenas igualdade com fontes e toolchain locais, não que estes sejam confiáveis.
3. Preparar o inventário completo com `buildManifest` e a identidade Git. A aprovação humana tem de indicar `candidateId`, `approvedBy`, `approvedAt`, `head`, `gitTree`, `entries` e `digest` exatos; o registo autorizado continua fora do repositório. Só após aprovação e CI validada executar o procedimento formal `source-freeze --write --approval <ficheiro-fora-do-repo>` com `CYBERSAFE_APPROVERS_FILE` configurado. O comando volta a reconstruir o launcher e recusa aprovação que não corresponda a HEAD, tree, contagem e digest; não cria aprovação.
4. O packaging valida o freeze, reconstrói o launcher de novo, compara os bytes e volta a verificar o freeze antes e depois do builder. Antes de promover, compara o launcher extraído do Setup e o de `win-unpacked` com os bytes aprovados. Uma falha deixa marca de não entregável. `--check` apenas inspeciona identidade e fontes; não reconstrói nem prova derivação.

O método exige reproduzibilidade dos bytes com a toolchain local. `/Brepro` não consta das tabelas públicas de opções MSVC; se a compilação ou comparação falhar após uma atualização, o gate falha fechado e requer investigação, não bypass. Consultar [CMake build](https://cmake.org/cmake/help/latest/manual/cmake.1.html) e [formato PE](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format). A comparação não substitui validação independente, assinatura, teste instalado ou aprovação de publicação.
